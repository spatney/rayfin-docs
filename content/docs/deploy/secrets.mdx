Rayfin manages application secrets — API keys, database passwords, third-party tokens —
separately from the public configuration in `rayfin.yml`. Secrets are read from a local
`.env` file, sent to your deployed Fabric app over an encrypted channel, and never appear
in client-side code or logs.

> [!WARNING]
> A **publishable key** (`pk-...`, the value in `rayfin/.deployments.json` and
> `RAYFIN_PUBLIC_PUBLISHABLE_KEY`) is safe to ship in client code — it identifies your
> project, not a credential. A **service secret** — an API key, a connection string, an
> auth token — is not. Never put a service secret in `RAYFIN_PUBLIC_*` variables, frontend
> code, or a place a browser can read it. Secrets defined with the `RAYFIN_SECRET_` prefix
> described below stay server-side.

## Define secrets

Create a `rayfin/.env` file with secrets prefixed `RAYFIN_SECRET_`:

```bash title="rayfin/.env"
RAYFIN_SECRET_API_KEY=sk-prod-abc123xyz789
RAYFIN_SECRET_DATABASE_PASSWORD=secure-db-pass-123
RAYFIN_SECRET_AUTH_TOKEN=token-abcdefg-hijklmn
RAYFIN_SECRET_OPENAI_KEY=sk-openai-your-key-here
```

The part of the variable name after `RAYFIN_SECRET_` becomes the secret's name — for
example, `RAYFIN_SECRET_API_KEY` creates a secret named `API_KEY`.

Never commit `rayfin/.env`. Add it to `.gitignore`:

```bash
echo "rayfin/.env" >> .gitignore
```

## Deploy before applying secrets

Secrets attach to an existing deployment, so deploy your project first if you haven't
already:

```bash
npx rayfin up
```

This creates your Fabric app and its workload endpoint.

## Apply secrets

```bash
npx rayfin up secrets apply
```

The CLI reads `rayfin/.env`, extracts every `RAYFIN_SECRET_*` variable, sends each one to
your workload over HTTPS, and validates that all of them persisted:

```text
🔐 Acquiring authentication token...
✓ Token acquired
📤 Sending 4 secret(s) to workload...
✓ Secrets sent to workload (4 persisted)
✅ Validating secrets persisted to workload...
✓ All secrets validated

✨ Secrets applied successfully (4/4)
  ✓ API_KEY
  ✓ DATABASE_PASSWORD
  ✓ AUTH_TOKEN
  ✓ OPENAI_KEY
```

```prompt title="Apply secrets to a deployed Rayfin app"
My Rayfin project already has secrets defined in rayfin/.env, prefixed with
RAYFIN_SECRET_. Deploy the project if it isn't already deployed with `npx rayfin up`, then
run `npx rayfin up secrets apply` to send those secrets to the deployed workload. Report
which secrets were applied and whether validation succeeded.
```

### Custom .env file location

If your secrets live somewhere other than `rayfin/.env`, point the CLI at that file with
`--env-file`:

```bash
npx rayfin up secrets apply --env-file ./config/secrets.env
```

| Flag | What it does |

## Secret handling and security

Secrets are transmitted over HTTPS with encrypted payloads, and the workload encrypts and
persists them server-side. They are never logged or displayed once sent.

**Best practices:**

- **Local development only** — never commit `.env` files. Set `RAYFIN_SECRET_*` variables
  directly in your CI/CD environment instead of checking in production values:

  ```bash
  export RAYFIN_SECRET_API_KEY=prod-key-from-vault
  npx rayfin up secrets apply
  ```

- **Rotate regularly** — re-run `rayfin up secrets apply` after updating a value in
  `.env`.
- **Separate environments** — use different `.env` files (with `--env-file`) or shell
  variables per environment, rather than one shared file for dev and production.

## Troubleshooting

### No secrets found

If the CLI reports "No secrets found in .env file", check that:

- `rayfin/.env` exists.
- Variables are prefixed with `RAYFIN_SECRET_`.
- The file is readable by the CLI process.

### Authentication failed

If you see "Failed to acquire authentication token":

- Run `npx rayfin login` to sign in.
- Confirm you have valid Entra ID credentials.
- On containers or restricted environments, add `--encryption-fallback-enabled` or set
  `RAYFIN_ENCRYPTION_FALLBACK_ENABLED=true`.

### Validation inconclusive

If some secrets fail validation:

- Check your network connection to Fabric.
- Run `npx rayfin up status` to confirm the workload endpoint is healthy.
- Re-run `npx rayfin up secrets apply` to retry.

### Permission denied

If you see permission errors:

- Confirm you're authenticated with an account that has access to the Fabric workspace.
- Confirm the correct workspace is selected.
- Run `npx rayfin login` again — the MSAL account picker is always shown, so you can
  choose a different account or tenant from there.
