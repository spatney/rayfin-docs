---

A Rayfin entity is a TypeScript class. Decorate it once and Rayfin generates the database
table, a GraphQL API, a type-safe client, row-level security, and form validation from
that single definition — there is no separate schema file, migration file, or API
contract to keep in sync by hand.

```typescript title="rayfin/data/Todo.ts"
import { entity, authenticated, uuid, text, boolean, date } from '@microsoft/rayfin-core';

@entity()
@authenticated('*', {
  policy: (claims, item) => claims.sub.eq(item.user_id),
})
export class Todo {
  @uuid() id!: string;
  @text({ max: 200 }) title!: string;
  @boolean({ default: false }) isCompleted!: boolean;
  @date() createdAt!: Date;
  @text({ max: 128 }) user_id!: string;
}
```

Register it in `schema.ts`, then apply it:

```bash
npx rayfin up
```

From there, `client.data.Todo` is a fully typed read/write API, scoped by the row-level
policy declared above.

## Set up the client

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Create one client with `RayfinClient.create` and reuse it across your app. Register the data
service with `dataService<AppSchema>()` so every entity access is fully typed. The 2.0 client
depends only on `@microsoft/rayfin-lib`, so install the auth and data packages yourself:

```bash
npm install @microsoft/rayfin-client @microsoft/rayfin-auth @microsoft/rayfin-data
```

```typescript title="src/services/rayfinClient.ts"
import { RayfinClient } from '@microsoft/rayfin-client';
import { browserSession } from '@microsoft/rayfin-auth';
import { dataService } from '@microsoft/rayfin-data';
import type { AppSchema } from '../../rayfin/data/schema';

export const rayfinClient = RayfinClient.create({
  baseUrl: import.meta.env.VITE_RAYFIN_API_URL,
  publishableKey: import.meta.env.VITE_RAYFIN_PUBLISHABLE_KEY,
  auth: browserSession({ storage: true }),
  services: {
    data: dataService<AppSchema>(),
  },
});

export type AppClient = typeof rayfinClient;
```

`VITE_RAYFIN_API_URL` and `VITE_RAYFIN_PUBLISHABLE_KEY` are generated into `.env.local` by
`rayfin dev` during development, and by deployment/environment commands for deployed flows — see [Schema changes](/docs/data/migrations) for the apply workflow that produces them.

The client exposes only what you register: `auth: browserSession()` adds
[`client.auth`](/docs/auth), and `services.data` adds `client.data`. The 1.x form
`new RayfinClient<AppSchema>(...)` was removed in 2.0, and the `EntitySchema` and
`TypedDataClients` types now come from `@microsoft/rayfin-data` instead of the client package.
See [`@microsoft/rayfin-client`](/docs/reference/sdk/rayfin-client) for every option and the
1.x migration. [Removed in 2.0](/docs/reference/changelog#rayfin-20)

Register other capabilities on the same client. `functionsService` from
`@microsoft/rayfin-functions` adds [`client.functions`](/docs/functions/calling-functions), and
`connectorsService` from `@microsoft/rayfin-connectors` adds `client.connectors` for existing
Fabric data sources — see [Wiring connectors into your app](/docs/connectors/client-setup).

```prompt title="Upgrade Rayfin data code to 2.0"
Upgrade the Rayfin data code in my project to Rayfin 2.0. Install @microsoft/rayfin-client,
@microsoft/rayfin-auth, @microsoft/rayfin-data, and @microsoft/rayfin-core at 2.0.0, and make
sure TypeScript is ^5.7.2 or ^6.0.2. Replace `new RayfinClient<AppSchema>(...)` with
`RayfinClient.create({ baseUrl, publishableKey, auth: browserSession({ storage: true }),
services: { data: dataService<AppSchema>() } })`, importing browserSession from
@microsoft/rayfin-auth and dataService from @microsoft/rayfin-data. Import EntitySchema and
TypedDataClients from @microsoft/rayfin-data, and anything imported from
@microsoft/rayfin-core/experimental from @microsoft/rayfin-core. Make every relative import
between files under rayfin/ end in .js.

Then fix queries and mutations for the 2.0 result types. Results contain only the fields passed
to .select(), and findById, findFirst(filter), and findMany(filter) return only the primary
key, so replace reads of other fields with .select([...]).where({ id: { eq: id } }).findFirst().
Always use the builder that .select() returns. Add the [] marker to every one-to-many selection
path ('notes.title' becomes 'notes[].title'). Convert selected date fields with new Date(value)
and boolean fields with value === true || value === 'true'. create and update now return only
the primary key plus the fields you passed, and delete returns only the primary key. Run the
type-checker and fix every remaining error.
```
