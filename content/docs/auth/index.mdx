Rayfin Auth gives your app managed Microsoft Entra sign-in, session handling, and token refresh.
After sign-in, `client.data.*` and `client.functions.*` calls use the authenticated context from the same `client.auth` instance.

## Why use Rayfin Auth

- **No separate identity provider to run** — Rayfin Fabric apps use Microsoft Entra ID through Fabric SSO or delegated Entra token exchange.
- **Pre-integrated SDK clients** — once a session is installed on `client.auth`, the client's registered services send the authenticated context automatically.
- **Per-user data isolation** — JWT claims drive row-level security policies declared on your entities, including app-defined [dynamic claims](/docs/auth/dynamic-claims). See [Permissions](/docs/data/permissions).
- **One session API** — `getSession`, `onSessionChange`, `refreshSession`, and `signOut` work the same way no matter which supported flow installed the session.

## Choose an auth path

| Situation | Use | Where it runs |
| --- | --- | --- |
| A browser app needs Fabric to perform interactive sign-in | [Fabric SSO popup flow](/docs/auth/fabric-sso) | Any origin in `services.auth.allowedRedirectUris`, including `http://localhost:5173` during local frontend development. |
| A Rayfin app is loaded inside the Fabric portal iframe | [Fabric SSO embedded flow](/docs/auth/fabric-sso#embedded-flow-automatic-sign-in-on-startup) | The Fabric portal iframe. The embedded flow requires the app to be loaded by Fabric. |
| A React app needs shared session state and route guarding | [React integration](/docs/auth/react) | Browser UI code, using the same `client.auth` instance as the SDK client. |
| Browser or Node.js code already has a delegated Entra token | [Direct Entra token sign-in](/docs/auth/entra-token) | Browser or Node.js. Requires Rayfin 1.36 or later and `externalEntraExchange: true`. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| Your own portal embeds a Rayfin app in an iframe | [External embed host](/docs/auth/embed-host) | Parent portal page plus the embedded Rayfin app. Requires Rayfin 1.36 or later and `externalEntraExchange: true`. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| UI code needs to react to sign-in, sign-out, or refresh | [Sessions](/docs/auth/sessions) | Any frontend code that can access `client.auth`. |
| Entity policies need app-defined facts about the user, such as an account or region | [Dynamic auth claims](/docs/auth/dynamic-claims) | A `udf.authClaims` function the backend calls at sign-in and refresh. [New in 2.0](/docs/reference/changelog#rayfin-20) |

Microsoft Entra ID is the only supported identity provider for Rayfin Fabric apps.
Do not add alternate sign-in UI to a new Rayfin app.

> [!NOTE]
> The Fabric SSO popup flow works from a local dev server as long as the origin is listed in `allowedRedirectUris`, including `http://localhost:5173`.
> Only the embedded iframe flow requires the app to be loaded inside the Fabric portal or by an external embed host.

## Enable auth for browser apps

For Fabric SSO, enable the auth service and the Fabric provider in `rayfin/rayfin.yml`:

```yaml title="rayfin/rayfin.yml"
services:
  auth:
    enabled: true
    allowedRedirectUris:
      - http://localhost:5173
    fabric:
      enabled: true
```

Run `npm run dev` for the development loop.
Scaffolded projects run `rayfin dev`, which provisions or reuses the managed Fabric backend, applies auth settings, writes `RAYFIN_PUBLIC_*` values to `rayfin/.env`, maps them to framework variables such as `VITE_FABRIC_ITEM_ID`, then starts the frontend.

Use `npx rayfin up` when you want to deploy static hosting or update a deployed environment without starting the local frontend.
See [Redirect URIs](/docs/hosting/redirect-uris) for what `allowedRedirectUris` controls.

## Create a client with a browser session

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Every sign-in flow installs its session on `client.auth`, which exists only when you create the client with `browserSession()` from `@microsoft/rayfin-auth`:

```bash
npm install @microsoft/rayfin-client @microsoft/rayfin-auth @microsoft/rayfin-auth-provider-fabric @microsoft/rayfin-data
```

```typescript title="src/services/rayfinClient.ts"
import { RayfinClient } from '@microsoft/rayfin-client';
import { browserSession } from '@microsoft/rayfin-auth';
import { dataService } from '@microsoft/rayfin-data';
import type { AppSchema } from '../../rayfin/data/schema';

export const client = RayfinClient.create({
  baseUrl: import.meta.env.VITE_RAYFIN_API_URL,
  publishableKey: import.meta.env.VITE_RAYFIN_PUBLISHABLE_KEY,
  auth: browserSession({ storage: true }),
  services: {
    data: dataService<AppSchema>(),
  },
});
```

Session options such as `storage`, `persistSession`, `autoRefreshToken`, and `multiTabSync` are arguments to `browserSession()`; in Rayfin 1.x they were top-level client options.
A client created with `suppliedToken()` from `@microsoft/rayfin-client` has no `client.auth` — use it only for scripts and servers that already hold a Rayfin token.
See [Sessions](/docs/auth/sessions#configure-session-options) for every option.

## Enable external Entra exchange

Direct Entra token sign-in and the external embed host call Rayfin's external brokered endpoints.
Add `externalEntraExchange: true` and deploy the setting before using those flows:

```yaml title="rayfin/rayfin.yml"
services:
  auth:
    enabled: true
    fabric:
      enabled: true
      externalEntraExchange: true
```

This opt-in is not needed for the normal Fabric SSO popup or Fabric iframe flows.

## Use sessions after any flow

Every flow installs the same opaque session on `client.auth`.
Read only the documented fields and subscribe with `onSessionChange`:

```typescript title="src/auth/session.ts"
import { client } from '../services/rayfinClient';

const session = client.auth.getSession();

if (session.isAuthenticated && session.user) {
  console.log('Signed in as', session.user.email);
}

const unsubscribe = client.auth.onSessionChange((nextSession) => {
  console.log('Auth changed:', nextSession?.isAuthenticated ?? false);
});

// Later, for example on component unmount:
unsubscribe();
```

`isAuthenticated` is `true` only while the access token is unexpired. [Changed in 2.0](/docs/reference/changelog#rayfin-20)
See [Sessions](/docs/auth/sessions) for refresh, sign-out, and lifecycle details.

## Show sign-in errors

`ensureSignedInWithFabric()` and `signInWithEntraToken()` reject with an `AuthError` when sign-in fails.
Catch it and show `error.message` in your sign-in UI; it is a user-safe description.
`initEmbeddedAuth()` resolves to `null` instead of rejecting, so show a sign-in button when it does.
See [Handle sign-in errors](/docs/auth/fabric-sso#handle-sign-in-errors) for the codes.
