Rayfin's email/password and magic-link sign-in are backed by Rayfin's own auth service, and
run against the local backend you get from `npx rayfin up` (or `npx rayfin dev` in Rayfin
Local).

> [!WARNING]
> Email and password (and magic link) is **local-development only**. A deployed Fabric app
> supports [Fabric SSO](/docs/auth/fabric-sso) exclusively. Build your sign-in UI so it uses
> password/magic-link auth locally and Fabric SSO once deployed — see
> [React integration](/docs/auth/react) for a pattern that switches automatically. See
> [Auth](/docs/auth) for the full picture.

## Enable password auth

Password auth is enabled by default whenever `services.auth` is enabled:

```yaml title="rayfin/rayfin.yml"
services:
  auth:
    enabled: true
    allowedRedirectUris:
      - http://localhost:5173
    password:
      enabled: true
```

Restart the backend after changing this file so the updated endpoints are exposed.

## Sign up and sign in

Signing up does **not** issue an access token — call `signIn()` immediately afterward to
obtain one. This two-step design leaves room for email-verification flows that gate sign-in
until the address is confirmed.

```typescript title="src/services/auth.ts"
import { RayfinClient } from '@microsoft/rayfin-client';

export const client = new RayfinClient({
  baseUrl: 'http://localhost:5168',
  publishableKey: 'pk-commonSampleAppKey',
});

async function registerAndSignIn(email: string, password: string) {
  // Step 1: create the account.
  const signUpResult = await client.auth.signUp({ email, password });
  console.log('User created:', signUpResult.userId);

  // Step 2: sign in to obtain an access token. Rayfin manages session
  // storage and token refresh internally from this point on.
  await client.auth.signIn({ email, password });

  const session = client.auth.getSession();
  console.log('Signed in:', session.user);

  // Data calls are now authenticated automatically.
  await client.data.Todo.getAll();
}

async function logOut() {
  await client.auth.signOut();
}
```

## Handling errors

Auth methods reject with an error you can read a `message` from directly:

```typescript
try {
  await client.auth.signIn({ email, password });
} catch (error) {
  console.error('Sign-in failed:', error instanceof Error ? error.message : error);
}
```

`@microsoft/rayfin-client` also exports an `AuthError` class with a `code` property, so you
can branch on specific failures — for example creating an account on first sign-in instead
of showing a generic error:

```typescript title="src/services/auth.ts"
import { AuthError, type RayfinClient } from '@microsoft/rayfin-client';

async function signInOrRegister(
  client: RayfinClient,
  email: string,
  password: string
) {
  try {
    await client.auth.signIn({ email, password });
  } catch (err) {
    // INVALID_GRANT covers both "wrong password" and "no such user" — the
    // backend does not distinguish them, to avoid leaking which emails are
    // registered. Only fall through to sign-up for that specific code.
    if (!(err instanceof AuthError) || err.code !== 'INVALID_GRANT') {
      throw err;
    }
    await client.auth.signUp({ email, password });
    await client.auth.signIn({ email, password });
  }
}
```

## Magic links

Magic links let a user sign in from an emailed link instead of typing a password. Enabling
them requires both the `passwordless.magicLink` flag and an email provider, since Rayfin has
to send the link:

```yaml title="rayfin/rayfin.yml"
services:
  auth:
    enabled: true
    allowedRedirectUris:
      - http://localhost:5173
    passwordless:
      magicLink:
        enabled: true
        expiryMinutes: 15
    email:
      enabled: true
      provider: smtp
      senderName: Rayfin Platform
      smtp:
        host: maildev
        port: 1025
        senderEmail: noreply@rayfin.local
        username: ""
        password: ""
        useSsl: false
        useStartTls: false
        webPort: 1080
```

### Sending the link

`redirectUri` is where the user lands after clicking the emailed link — it must be one of
your app's own routes, and its origin should be listed in `allowedRedirectUris` (see
[Redirect URIs](/docs/hosting/redirect-uris)).

```typescript title="src/services/auth.ts"
async function sendLoginLink(email: string) {
  const result = await client.auth.sendMagicLink({
    email,
    redirectUri: `${window.location.origin}/auth/callback`,
  });
  // `state` correlates this request with the callback below; the SDK
  // stores it (and the PKCE verifier) in localStorage for you.
  console.log('Magic link sent, state:', result.state);
}
```

### Handling the callback

On the page the link redirects to, check whether the URL is a magic-link callback and
complete the exchange:

```typescript title="src/pages/AuthCallback.tsx"
import { useEffect, useState } from 'react';
import { client } from '../services/auth';

export function AuthCallback() {
  const [status, setStatus] = useState<'working' | 'done' | 'error'>('working');

  useEffect(() => {
    if (!client.auth.isMagicLinkCallback()) {
      setStatus('error');
      return;
    }

    client.auth.handleMagicLinkCallback().then((result) => {
      if (result.success) {
        setStatus('done');
        window.location.assign('/');
      } else {
        console.error('Magic link sign-in failed:', result.error);
        setStatus('error');
      }
    });
  }, []);

  if (status === 'working') return <p>Signing you in…</p>;
  if (status === 'error') return <p>That sign-in link is invalid or has expired.</p>;
  return null;
}
```

`handleMagicLinkCallback()` reads the verification code and state from the URL (it defaults
to `window.location.href`), retrieves the PKCE verifier that `sendMagicLink` stored, and
exchanges the code for tokens. On success it creates a session the same way `signIn()` does.

## `allowedRedirectUris`

Rayfin does not silently accept any `redirectUri` you pass to `sendMagicLink` — the field
covers redirect URIs for auth callbacks generally, including magic-link callbacks and the
Fabric SSO handoff. Keep it scoped to your app's own origins. See
[Redirect URIs](/docs/hosting/redirect-uris) for the full configuration reference, including
what `rayfin up` appends automatically when static hosting is enabled.
