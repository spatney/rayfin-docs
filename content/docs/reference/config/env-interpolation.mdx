---
title: Environment variable interpolation
description: Use ${VAR} and ${VAR:-default} in rayfin.yml with Rayfin's .env resolution, type coercion, and missing-variable errors.
---

`rayfin.yml` supports shell-style interpolation so environment-specific values stay out of
committed configuration.

## Syntax

| Syntax | Meaning |
| --- | --- |
| `${VAR}` | Substitute `VAR`; error if unset or empty. |
| `${VAR:-default}` | Substitute `VAR`, or `default` when unset or empty. |

```bash title="rayfin/.env"
DEFINED=value
EMPTY=
```

```yaml title="rayfin/rayfin.yml"
config1: ${DEFINED}
config2: ${EMPTY:-fallback}
config3: ${UNDEFINED:-fallback}
```

## Usage

### Basic substitution

```yaml title="rayfin/rayfin.yml"
services:
  data:
    enabled: true
    dialect: ${DB_DIALECT:-mssql}
  auth:
    enabled: true
    fabric:
      enabled: true
    allowedRedirectUris:
      - https://${APP_HOSTNAME}/callback
```

```bash title="rayfin/.env.example"
DB_DIALECT=mssql
APP_HOSTNAME=example.contoso.com
```

### Default values

```yaml title="rayfin/rayfin.yml"
services:
  data:
    dialect: ${DB_DIALECT:-mssql}
```

### Partial interpolation

```yaml title="rayfin/rayfin.yml"
services:
  auth:
    allowedRedirectUris:
      - https://${APP_HOSTNAME}/callback
```

## `.env` file location

By default, Rayfin loads `rayfin/.env`. Override it with a command flag or shell variable:

```bash
npx rayfin up --env-file .\deploy\production.env
```

```bash
set RAYFIN_ENV_FILE=.\deploy\staging.env
npx rayfin up
```

## Resolution priority

1. Shell environment variables, when non-empty.
2. Variables from `--env-file <path>` or `RAYFIN_ENV_FILE`, when non-empty.
3. Variables from `rayfin/.env`, when non-empty.
4. Default values from `${VAR:-default}`.
5. Error when no value or default exists.

See [Environment variables](/docs/reference/config/environment-variables) for the broader
CLI environment reference.

## Type coercion

When the entire YAML value is one interpolation expression, Rayfin coerces strings to the
matching YAML scalar type:

```yaml title="rayfin/rayfin.yml"
services:
  data:
    enabled: ${DATA_ENABLED}
    dialect: ${DB_DIALECT:-mssql}
  auth:
    expiryInMinutes: ${TOKEN_EXPIRY_MINUTES:-60}
```

```bash title="rayfin/.env"
DATA_ENABLED=true
TOKEN_EXPIRY_MINUTES=60
```

Partial interpolation always returns a string:

```yaml title="rayfin/rayfin.yml"
services:
  staticHosting:
    folder: dist-${BUILD_NUMBER}
```

## Error handling

A required missing variable fails before deployment:

```text
❌ Environment variable 'DB_HOST' referenced in rayfin.yml (services.data.host) is not defined.
   Set it in .env file or shell environment.
```

## Security best practices

- Do not commit `rayfin/.env`; it is gitignored by scaffolded projects.
- Commit `rayfin/.env.example` with placeholders for required variables.
- Use CI secret variables for deployment secrets.
- Omit defaults for values that must be supplied intentionally.

```prompt title="Parameterize a rayfin.yml value"
Update rayfin/rayfin.yml so `services.data.dialect` reads from `${DB_DIALECT:-mssql}`.
Add `DB_DIALECT=mssql` to rayfin/.env.example, then run `npx rayfin up --dry-run` to
confirm interpolation resolves.
```
