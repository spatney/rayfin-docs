title: rayfin.yml reference
description: Complete Rayfin 2.0.0 rayfin.yml schema — auth and dynamic claims, data, static hosting, Functions, storage, telemetry, connectors, and secrets.
---

`rayfin/rayfin.yml` is the committed project configuration. The CLI reads it for `rayfin
dev`, `rayfin up`, `rayfin env`, Functions, connectors, and secret type generation.

## Top-level keys

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | Project identifier. `rayfin up` uses it as the default Fabric item display name. |
| `name` | string | yes | Human-readable project name. |
| `version` | string | yes | Project version string written by scaffolding. |
| `services` | object | yes | Service configuration. |
| `connectors` | array | no | External data connector entries. The parser also tolerates legacy map shape on read. |
| `secrets` | array | no | Secret declarations used by Functions typing. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| `frontend` | object | no | Deprecated; framework is auto-detected at runtime. |
| `publishable_key` | string | no | Legacy. Current CLI writes `RAYFIN_PUBLIC_PUBLISHABLE_KEY` to `rayfin/.env`. |

## `services.auth`

Microsoft Entra ID through Fabric SSO is the supported identity provider.

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | Turns Auth on or off. |
| `fabric.enabled` | boolean | when Auth is enabled | Enables Fabric brokered auth. |
| `fabric.externalEntraExchange` | boolean | no | Allows callers that already hold a delegated Entra token to exchange it for a Rayfin session through external brokered endpoints. Defaults to absent/false. |
| `allowedRedirectUris` | string[] | no | Redirect origins accepted by Auth. `rayfin dev` and `rayfin up` add local dev and hosted origins. |
| `expiryInMinutes` | number | no | Session token lifetime. |
| `customClaims` | `Record<string, string>` | no | Static custom claims added to issued tokens. Dynamic claim names must not collide with these. |
| `dynamicClaims.enabled` | boolean | no | Turns [dynamic auth claims](/docs/auth/dynamic-claims) on or off. Declaring `dynamicClaims` at all, even with `enabled: false`, makes the CLI generate the claims contract from your `udf.authClaims` provider. Requires Functions. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `scopes` | string[] | no | OAuth scopes. |
| `refreshToken.lifetimeInDays` | number | no | Refresh token lifetime. |

Do not author `dynamicClaims.contract`. Deploys that ship functions fill it in from the
generated `auth/claims.contract.json`, and every other settings write keeps the contract
the backend already has. The `dynamicclaims` value of `RAYFIN_FEATURE_FLAGS` is retired:
the CLI fails if it is set without a `services.auth.dynamicClaims` declaration.


## `services.data`

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | Turns Data on or off. |
| `dialect` | `mssql` | when enabled | Database dialect. Fabric supports `mssql`. |
| `allowIntrospection` | boolean | no | Enables GraphQL `__schema` / `__type` introspection. Defaults to false when omitted. |
| `path` | string | no | Data package directory relative to the project root. |
| `buildCommand` | string | no | Command to run before entity compilation. |

## `services.staticHosting`

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | Turns static hosting on or off. |
| `path` | string | no | Frontend package directory relative to the project root. |
| `root` | string | no | Frontend root relative to `path` or project root. Absolute and parent-traversing values are invalid. |
| `folder` | string | when enabled | Build output folder relative to `root`. |
| `buildCommand` | string | no | Command to run before deploy. |
| `indexDocument` | string | no | Default document, usually `index.html`. |
| `assetAccess` | `protected` \| `public` | required for static-hosted deploys | Who can load hosted assets: `protected` requires Fabric sign-in, `public` serves anyone with the link. Replaces `anonymousAccess`. New projects scaffold `protected`, and non-interactive `rayfin up` writes `protected` when it is missing. [New in 1.35.1](/docs/reference/changelog#rayfin-1351) |
| `embedded.only` | boolean | no | Whether the app loads only inside the Fabric portal. |

Older projects may omit `assetAccess`. Choose explicitly before deployment; do not rely on
implicit access changes.

## `services.functions`

[Changed in 1.36](/docs/reference/changelog#rayfin-136)

Functions no longer need a feature flag, and enabled Functions must declare
`auth.type: application`.

> [!NOTE]
> Functions are not available in every Fabric region or tenant.

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | Turns Functions on or off. |
| `auth.type` | `application` | required when enabled | Artifact-level Functions authentication. No default is applied during validation; `rayfin init --services functions` and `rayfin functions init` scaffold it. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| `path` | string | no | Functions package directory relative to the project root. Defaults to `rayfin/functions`. |
| `buildCommand` | string | no | Build command before local run or deploy. Defaults to `npm run build` in local Functions tooling when omitted. |

Functions that call Rayfin data through `ctx.getDataClient()` remain caller-scoped to the
invocation's Rayfin token. Functions that use declared external connections through
`ctx.Tokens.<Audience>` receive app-identity tokens for the configured audience, not the
signed-in user's delegated token.

Invalid Functions config fails with exact messages such as:

```text
Invalid services.functions.auth: authentication is required when Functions are enabled. Set services.functions.auth.type to "application".
```

## `services.storage`

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Storage is generally available and needs no feature flag. It is remote-only: folder
declarations apply to the deployed Fabric backend. `rayfin storage init` sets this block for
you. See [Storage](/docs/storage).

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes | Turns Storage on or off. |
| `path` | string | no | Storage package directory relative to the project root. |

Storage depends on Data; `rayfin init` rejects `storage` without `data`. Storage stays
enabled when no folders are declared, but `rayfin up` and `rayfin dev` skip the Storage
apply step with a warning until at least one `@blob` folder is registered.

## `services.telemetry`

[New in 2.0](/docs/reference/changelog#rayfin-20) [Experimental](/docs/reference/changelog#feature-status)

Application telemetry for [Observability](/docs/deploy/observability). `rayfin telemetry
enable` and `rayfin telemetry disable` edit this block; deploy with `rayfin up` to apply
the change.

> [!WARNING]
> Provisioning requires Fabric service-side enablement for the target workspace. Setting
> `enabled: false` and running `rayfin up` deletes the app's Application Insights resource
> and the telemetry it collected.

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `enabled` | boolean | yes, when the block is present | Turns application telemetry on or off. Do not put a connection string or resource ID here; the backend allocates and stores them. |

## `services.connectors`

| Key | Type | Description |
| --- | --- | --- |
| `enabled` | boolean | Deprecated no-op. Connectors are generally available and the CLI command group is always registered. [Changed in 1.36](/docs/reference/changelog#rayfin-136) |

Do not add this block to new configs.

## `connectors`

Top-level `connectors` is an array. See [Connector](/docs/reference/cli/connector) for the
command reference.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | yes | Unique connector name, 1–256 chars, alphanumeric plus hyphen and underscore. Names are case-insensitive: two entries that differ only by case fail validation, and `rayfin connector add` stores new names in lowercase. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `type` | connector type | yes | `fabric-sqlanalytics`, `fabric-warehouse`, `fabric-sqldatabase`, `fabric-semanticmodel`, `fabriciqmcp`, or existing `eventhouse`. |
| `version` | positive integer string | Category B | Required for `fabric-semanticmodel`, `fabriciqmcp`, and `eventhouse`, for example `'1'`. |
| `config.workspaceId` | string | item-backed connectors | Fabric workspace ID. `fabriciqmcp` is itemless and uses `config: {}`. |
| `config.itemId` | string | item-backed connectors | Fabric item ID. |
| `auth.type` | `delegated` \| `application` | yes | Required, and validated against the type's allowed identities in the table below. `rayfin connector add` writes the type's default unless you pass `--auth`. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `operations[].name` | operation | no | Subset of allowed operations; omit for all allowed operations. |
| `additionalPayload` | object | no | Connector-defined JSON object saved with the connector's runtime settings. Category B only; Eventhouse uses it for saved queries. Kept verbatim — no `${VAR}` interpolation — and limited to 64 KiB of compact JSON and 32 levels of nesting. Not a secret store. [New in 2.0](/docs/reference/changelog#rayfin-20) |

| Type | Category | Default auth | Allowed auth | Operations | Authoring status |
| --- | --- | --- | --- | --- | --- |
| `fabric-sqlanalytics` | Category A | `application` | `delegated`, `application` | `read` | Released |
| `fabric-warehouse` | Category A | `application` | `delegated`, `application` | `read`, `create`, `update`, `delete` | Released |
| `fabric-sqldatabase` | Category A | `application` | `delegated`, `application` | `read`, `create`, `update`, `delete` | Released |
| `fabric-semanticmodel` | Category B | `delegated` | `delegated` | `executeQuery` | Released |
| `fabriciqmcp` | Category B | `delegated` | `delegated` | `executeQuery` | Released. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `eventhouse` | Category B | `application` | `application` | `executeQuery`, `executeCommand` | Held: existing declarations validate and deploy, but `rayfin connector add` rejects new Eventhouse connectors. Renamed from `kusto`. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |

`type: kusto` is rejected as an unknown connector type. Change it to `type: eventhouse`
and follow [Eventhouse](/docs/connectors/eventhouse) to move the connector to saved
queries. [Removed in 2.0](/docs/reference/changelog#rayfin-20)

## `secrets`

[New in 1.36](/docs/reference/changelog#rayfin-136)

`rayfin secret set --describe="..."` appends declarations here. Values are never stored in
`rayfin.yml`; only names and descriptions are committed.

```yaml title="rayfin/rayfin.yml"
secrets:
  - name: STRIPE_API_KEY
    description: API key used by payment functions
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | yes | Secret name used by `ctx.Secrets.<NAME>` and type generation. |
| `description` | string | no | Human-readable description. When omitted from `rayfin secret set`, the CLI writes `TODO: Add description for this secret`. |

## Complete example

```yaml title="rayfin/rayfin.yml"
id: universal-app
name: Universal App
version: 1.0.0
services:
  auth:
    enabled: true
    fabric:
      enabled: true
      externalEntraExchange: true
    allowedRedirectUris:
      - http://localhost:5173
  data:
    enabled: true
    dialect: mssql
    allowIntrospection: false
  staticHosting:
    enabled: true
    path: packages/frontend
    folder: dist
    buildCommand: npm run build:fabric
    indexDocument: index.html
    assetAccess: protected
    embedded:
      only: false
  functions:
    enabled: true
    path: packages/functions
    buildCommand: npm run build
    auth:
      type: application
  storage:
    enabled: false
connectors:
  - name: sales_warehouse
    type: fabric-warehouse
    config:
      workspaceId: 00000000-0000-0000-0000-000000000000
      itemId: 11111111-1111-1111-1111-111111111111
    auth:
      type: application
secrets:
  - name: STRIPE_API_KEY
    description: API key used by payment functions
```

## Environment interpolation

Any value may use `${VAR}` or `${VAR:-default}`. See
[Environment variable interpolation](/docs/reference/config/env-interpolation).

```prompt title="Update rayfin.yml for Rayfin 2.0"
Read rayfin/rayfin.yml and update it for Rayfin 2.0. Add
`services.staticHosting.assetAccess: protected` if static hosting is enabled and it is
missing, add `services.functions.auth.type: application` if Functions are enabled, and
remove `services.connectors.enabled`. If a connector declares `type: kusto`, stop and tell
me: it must become `type: eventhouse` with `auth.type: application` and saved queries in
`additionalPayload`, following https://rayfin.ai/docs/connectors/eventhouse.md. If
RAYFIN_FEATURE_FLAGS in my environment or rayfin/.env contains `storage` or
`dynamicclaims`, remove those values; for `dynamicclaims`, add
`services.auth.dynamicClaims.enabled: true` instead. Then run `npx rayfin up --dry-run` and
report the result.
```
