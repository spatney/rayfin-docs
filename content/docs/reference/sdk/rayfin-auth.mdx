`@microsoft/rayfin-auth` manages Rayfin session lifecycle, token refresh, event listeners, claims, and sign-out.
Most apps use it through `browserSession()`, which gives a [`RayfinClient`](/docs/reference/sdk/rayfin-client) its `client.auth`, rather than constructing `Auth` directly.

Microsoft Entra sign-in is provided by [`@microsoft/rayfin-auth-provider-fabric`](/docs/reference/sdk/rayfin-auth-provider-fabric), which installs sessions on this same `Auth` instance.

## Installation

```bash
npm install @microsoft/rayfin-auth
```

Install it directly: `@microsoft/rayfin-client` no longer depends on it, and your code imports `browserSession` from it. [Changed in 2.0](/docs/reference/changelog#rayfin-20)
Add `@microsoft/rayfin-lib` when you construct `Auth` with your own `ApiClient`.
The package declares an `exports` map, so import from `@microsoft/rayfin-auth` only, never from a `dist/` path.

## browserSession

[New in 2.0](/docs/reference/changelog#rayfin-20)

```typescript
function browserSession(options?: AuthOptions): ClientAuthFactory<Auth>;
```

Selects browser-session authentication for `RayfinClient.create()`.
The factory creates an `Auth` on the client's shared transport, attaches it before any registered service initializes, and exposes it as `client.auth`.

```typescript title="src/services/rayfinClient.ts"
import { RayfinClient } from '@microsoft/rayfin-client';
import { browserSession } from '@microsoft/rayfin-auth';
import { dataService } from '@microsoft/rayfin-data';
import type { AppSchema } from '../../rayfin/data/schema';

export const client = RayfinClient.create({
  baseUrl: import.meta.env.VITE_RAYFIN_API_URL,
  publishableKey: import.meta.env.VITE_RAYFIN_PUBLISHABLE_KEY,
  auth: browserSession({ storage: true }),
  services: {
    data: dataService<AppSchema>(),
  },
});
```

- `options` is the same [`AuthOptions`](#authoptions) object the `Auth` constructor takes.
- `client.auth` is an ordinary `Auth` instance. Pass it to every `@microsoft/rayfin-auth-provider-fabric` function.
- `client.dispose()` calls `Auth.destroy()`. It does not sign out, revoke tokens, or delete the persisted session.
- In Rayfin 1.x, `authStorage`, `persistSession`, `autoRefreshToken`, and `multiTabSync` were top-level client options. Pass them to `browserSession()` instead, with `authStorage` renamed to `storage`; `RayfinClient.create()` rejects them with `INVALID_AUTH_CONFIG`.
- A client created with `suppliedToken()` from `@microsoft/rayfin-client` has no `client.auth`.
- The adapter also works in Node.js. Pass `{ storage: false }` for a memory-only session.

## Auth constructor

```typescript
class Auth {
  constructor(apiClient: ApiClient, options?: AuthOptions);
}
```

Use the constructor for integrations that do not use `RayfinClient`.
Rayfin's auth SDK detects browser and non-browser runtimes.
When `window` is unavailable, it skips browser-only APIs such as `localStorage` unless you supply custom storage.
Use `{ storage: false }` for Node.js scripts or server code where no browser storage should be touched.

```typescript title="scripts/createAuth.ts"
import { Auth } from '@microsoft/rayfin-auth';
import { ApiClient } from '@microsoft/rayfin-lib';

const apiClient = new ApiClient({
  baseUrl: process.env.RAYFIN_API_URL!,
  publishableKey: process.env.RAYFIN_PUBLISHABLE_KEY!,
});

const auth = new Auth(apiClient, { storage: false });
auth.attachToClient(apiClient);

try {
  console.log('Authenticated:', auth.getSession().isAuthenticated);
} finally {
  auth.destroy();
}
```

## AuthOptions

```typescript
interface AuthOptions {
  storage?: AuthStorage | boolean;
  storageKeyPrefix?: string;
  persistSession?: boolean;
  autoRefreshToken?: boolean;
  multiTabSync?: boolean;
  refreshTimeout?: number;
}

interface AuthStorage {
  getItem(key: string): string | null | Promise<string | null>;
  setItem(key: string, value: string): void | Promise<void>;
  removeItem(key: string): void | Promise<void>;
  clear?(): void | Promise<void>;
  keys?(prefix: string): string[] | Promise<string[]>;
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `storage` | `AuthStorage \| boolean` | Browser `localStorage` when available | Storage implementation, `true` for default storage, or `false` for memory-only sessions. |
| `storageKeyPrefix` | `string` | None | Prefix for the stored session and PKCE keys. |
| `persistSession` | `boolean` | `true` | When `false`, skips all storage I/O and keeps sessions in memory. |
| `autoRefreshToken` | `boolean` | `true` | When `false`, disables refresh timers and automatic refresh on `401`. |
| `multiTabSync` | `boolean` | Auto-detected in browsers | When `false`, disables `StorageEvent` cross-tab session sync. |
| `refreshTimeout` | `number` | `10000` | Milliseconds allowed for the renewal that runs before a request whose access token expires within 60 seconds. Independent of per-request timeouts. [New in 2.0](/docs/reference/changelog#rayfin-20) |

## Session management

| Method | Signature | Description |
| --- | --- | --- |
| `getSession` | `() => OpaqueSession` | Returns the current public session synchronously. |
| `onSessionChange` | `(callback: (session: OpaqueSession \| null) => void) => () => void` | Subscribes to session changes and returns an unsubscribe function. |
| `getClaims` | `() => Promise<ClientClaims>` | Validates the current access token and returns its claims without exposing the token. See [Claims](#claims). [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `hasRefreshToken` | `() => boolean` | Returns whether a refresh token is available. |
| `refreshSession` | `(options?: { timeout?: number; signal?: AbortSignal }) => Promise<TokenResponse>` | Refreshes the session; concurrent refreshes share one in-flight request. `timeout` (milliseconds) and `signal` bound the call. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `attachToClient` | `(client: ApiClient) => void` | Adds authorization injection and refresh on `401` to another `ApiClient`, and renews a token that expires within 60 seconds before sending a request. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `destroy` | `() => void` | Removes timers and listeners. New or queued refreshes then reject with `AUTH_DESTROYED`; it does not sign out. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `startAutoRefresh` | `() => Promise<void>` | Restarts scheduled refresh when `autoRefreshToken: false` is used. |
| `stopAutoRefresh` | `() => void` | Stops scheduled refresh when `autoRefreshToken: false` is used. |

```typescript title="src/auth/sessionLog.ts"
import { client } from '../services/rayfinClient';

const session = client.auth.getSession();
console.log('Authenticated now:', session.isAuthenticated);

const unsubscribe = client.auth.onSessionChange((nextSession) => {
  console.log('Authenticated:', nextSession?.isAuthenticated ?? false);
});

// Later:
unsubscribe();
```

> [!WARNING]
> The session-change callback is `onSessionChange`.
> `onAuthStateChange` is not part of this SDK.

Rayfin renews the access token up to 60 seconds before it expires and retries transient renewal failures after 5 seconds, doubling up to 60 seconds. [Changed in 2.0](/docs/reference/changelog#rayfin-20)
See [Sessions](/docs/auth/sessions#how-rayfin-renews-tokens) for the full renewal, multi-tab, and sign-out behavior.

## OpaqueSession

Session objects are opaque by design.
Gate UI logic on `isAuthenticated` or the presence of `user`, not on internal fields.

```typescript
interface OpaqueSession {
  user: User | null;
  role?: string;
  expiresAt?: Date;
  isAuthenticated: boolean;
  isAnonymous: boolean;
}

interface User {
  id: string;
  email: string;
  role?: string;
  emailVerified?: boolean;
  emailVerifiedAt?: string | null;
}
```

`isAuthenticated` is `true` only while the session holds an access token that has not expired. [Changed in 2.0](/docs/reference/changelog#rayfin-20)
While an expired token waits to be renewed — for example after the device slept or was offline — it is `false`, `user` stays set, and `hasRefreshToken()` returns `true`; Rayfin renews the token automatically and emits `AUTH_REFRESH`.

## Claims

[New in 2.0](/docs/reference/changelog#rayfin-20)

```typescript
getClaims(): Promise<ClientClaims>;
```

Validates the current access token's signature and claims, then returns them: the base claims `sub`, `email`, and `role`, plus any [dynamic claims](/docs/auth/dynamic-claims) your app mints.
Tokens carry every app-defined claim as a string, so `ClientClaims` types each one as `string`; a provider's `false` arrives as `'false'`.
Server-side policies and a function's `ctx.getClaims()` see the declared types.

The claims types are exported from `@microsoft/rayfin-core`:

```typescript
interface RayfinBaseClaims {
  sub: string;
  email: string;
  role: string;
}

// Empty by default. The generated rayfin/auth/claims.generated.d.ts merges your claims in.
interface RayfinCustomClaims {}

type AllClaims = RayfinBaseClaims & RayfinCustomClaims;

type ClientClaims = RayfinBaseClaims & {
  [K in keyof RayfinCustomClaims]: string;
};
```

`getClaims()` rejects with `NO_SESSION`, `CLAIMS_VALIDATION_FAILED`, or `CLAIMS_DECODE_FAILED`.
Use the result for UI hints and keep authorization in entity policies.

## TokenResponse

```typescript
interface TokenResponse {
  accessToken: string;
  tokenType: string;
  expiresIn: number;
  refreshToken?: string | null;
  scope?: string | null;
}
```

Provider packages consume `TokenResponse` internally to install a public `OpaqueSession`.
Application code should not copy Rayfin tokens between clients.

## Sign-out methods

| Method | Signature | Description |
| --- | --- | --- |
| `signOut` | `() => Promise<void>` | Revokes the current access token and clears the local session. Renews a lapsed access token first so the revocation is accepted. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `signOutAll` | `() => Promise<SignOutAllResponse>` | Revokes every active session for the user and returns `{ count }`. |

`signOut()` clears the local session even when the server call fails, then rethrows the error.
A refresh that completes after sign-out no longer restores the session. [Changed in 2.0](/docs/reference/changelog#rayfin-20)

```typescript title="src/auth/signOutEverywhere.ts"
import { client } from '../services/rayfinClient';

export async function signOutEverywhere(): Promise<number> {
  const result = await client.auth.signOutAll();
  return result.count;
}
```

| `getAuthSettings` | `() => Promise<AuthSettingsConfig>` | Fetches public auth settings from the backend. |

## Events

Use `onSessionChange` for UI state.
For narrower lifecycle handling, subscribe to session events with `on(event, handler)`.
The signature uses the exported `AuthEvent` union:

```typescript
import type { AuthEvent, OpaqueSession } from '@microsoft/rayfin-auth';

function on(event: AuthEvent, handler: (session: OpaqueSession) => void): () => void;
```

The exported union contains every auth event emitted by the SDK. Fabric apps usually care
about these session lifecycle events, which also trigger `onSessionChange`:

| Event | Fires when |
| --- | --- |
| `AUTH_LOGIN` | A session is established. Subscribing while a session exists calls the handler immediately. |
| `AUTH_LOGOUT` | The session is cleared — by sign-out in this tab or another tab, or because it ended. |
| `AUTH_REFRESH` | The access token is renewed, or this tab adopts a session renewed in another tab. |
| `AUTH_SESSION_EXPIRED` | The session ends because its token lapsed and could not be renewed. |

```typescript title="src/auth/onExpired.ts"
import { client } from '../services/rayfinClient';

client.auth.on('AUTH_SESSION_EXPIRED', () => {
  window.location.assign('/sign-in');
});
```

## Error codes

Methods reject with `AuthError` from `@microsoft/rayfin-lib`, which `@microsoft/rayfin-client` re-exports.

| Code | Raised by | Meaning |
| --- | --- | --- |
| `NO_SESSION` | `refreshSession()`, `getClaims()`, `signOutAll()` | No session is active. |
| `NO_REFRESH_TOKEN` | `refreshSession()` | The session has no refresh token. |
| `REFRESH_BACKOFF` | `refreshSession()` | A recent renewal failed transiently; try again after the backoff window. |
| `SESSION_EXPIRED` | `refreshSession()` | The refresh token was rejected and the session ended. |
| `AUTH_DESTROYED` | `refreshSession()` | The `Auth` instance was destroyed, for example by `client.dispose()`. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `CLAIMS_VALIDATION_FAILED` | `getClaims()` | The current access token could not be validated. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `CLAIMS_DECODE_FAILED` | `getClaims()` | The current access token's claims could not be decoded. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `SIGN_IN_DENIED` | `refreshSession()`, provider sign-in | The app's dynamic claims function denied the user; on refresh the session also ends. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `AUTH_CLAIMS_UNAVAILABLE`, `AUTH_CLAIMS_FAILED`, `AUTH_CLAIMS_INVALID_OUTPUT` | `refreshSession()`, provider sign-in | The app's dynamic claims function timed out, failed, or returned claims that do not match its contract. See [Dynamic auth claims](/docs/auth/dynamic-claims#handle-sign-in-errors). [New in 2.0](/docs/reference/changelog#rayfin-20) |

## React usage

```typescript title="src/hooks/useSession.ts"
import { useEffect, useState } from 'react';
import type { OpaqueSession } from '@microsoft/rayfin-auth';
import { client } from '../services/rayfinClient';

export function useSession() {
  const [session, setSession] = useState<OpaqueSession | null>(null);

  useEffect(() => {
    setSession(client.auth.getSession());
    return client.auth.onSessionChange(setSession);
  }, []);

  return {
    session,
    isAuthenticated: session?.isAuthenticated ?? false,
    signOut: () => client.auth.signOut(),
  };
}
```

Wire sign-in separately with [`ensureSignedInWithFabric`](/docs/reference/sdk/rayfin-auth-provider-fabric), [`signInWithEntraToken`](/docs/reference/sdk/rayfin-auth-provider-fabric#signinwithentratoken), or the local development helper that installs a brokered token.
For Fabric apps, await `initEmbeddedAuth()` before trusting the first session; see [React integration](/docs/auth/react).

## AuthApi provider integration

`auth.getAuthApi()` returns the lower-level `AuthApi` used by companion provider packages.
Rayfin 1.36 adds `getBrokeredAuthorizeExternalUrl()` so the external embed flow can tell the parent host which endpoint to call. [New in 1.36](/docs/reference/changelog#rayfin-136)

```typescript
class AuthApi {
  getBrokeredAuthorizeExternalUrl(): string;
  exchangeVerificationCode(request: VerificationCodeExchangeRequest): Promise<TokenResponse>;
  getAuthSettings(): Promise<AuthSettingsConfig>;
}
```

Builders using `ensureSignedInWithFabric()` or `createEmbedHost()` do not call `getBrokeredAuthorizeExternalUrl()` directly.
The provider SDK includes it in the external-embed handshake.

## Performance marks

[New in 2.0](/docs/reference/changelog#rayfin-20)

Token renewal records `rayfin:refresh-start` and `rayfin:refresh-end` User Timing marks and a `rayfin:refresh` measure.
They appear in the browser's performance tools and can be collected with a `PerformanceObserver` for the `mark` and `measure` entry types.
The marks never contain tokens and are skipped where the User Timing API is unavailable.

## Configuration and restart behavior

Auth is configured in `rayfin.yml` under `services.auth`.
After changing values such as `enabled`, `allowedRedirectUris`, `fabric.enabled`, `fabric.externalEntraExchange`, or `dynamicClaims.enabled`, apply the updated runtime settings with `npm run dev` or `npx rayfin up`.
A running backend does not infer local config changes until they are applied.
