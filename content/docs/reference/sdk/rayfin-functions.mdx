[Changed in 1.36](/docs/reference/changelog#rayfin-136)

`@microsoft/rayfin-functions` is the client-side SDK package behind `client.functions.<name>.invoke(...)`. Server-side function authoring uses `@microsoft/fabric-user-data-functions`; see [Writing a function](/docs/functions/writing-functions).

## Installation

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Install the package in every app that calls functions, at the same version as `@microsoft/rayfin-client`. In 1.x the client pulled it in; the 2.0 client depends only on `@microsoft/rayfin-lib`.

```bash
npm install @microsoft/rayfin-functions@2.0.0
```

## Exports

| Export | Kind | Purpose |
| --- | --- | --- |
| `functionsService<TSchema>()` | Function | Registers typed `client.functions` on a client built with `RayfinClient.create`. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `FunctionClient<TInput, TOutput>` | Class | Client for one named function. |
| `FunctionsError` | Class | Function invocation error extending `SdkError`. |
| `createFunctionsApi<TSchema>(apiClient)` | Function | Creates the typed functions proxy for code that already owns an `ApiClient`. |
| `FunctionInvocationResponse<TOutput>` | Type | Transport envelope returned by the backend before `invoke()` unwraps `output`. |
| `InvokeOptions` | Type | Per-call headers and timeout. |
| `FunctionsSchema` | Type | Map of function names to `{ input, output }`. Import it from this package; `@microsoft/rayfin-client` no longer re-exports it. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `TypedFunctionClients<TSchema>` | Type | Map from schema keys to typed `FunctionClient` instances. |

## `functionsService`

[New in 2.0](/docs/reference/changelog#rayfin-20)

```typescript
function functionsService<TSchema extends FunctionsSchema>(): ClientServiceFactory<
  TypedFunctionClients<TSchema>
>;
```

Register the factory under `services` when you create the client. The key you choose becomes the namespace on the client; use `functions`:

```typescript title="src/services/rayfinClient.ts"
import { RayfinClient } from '@microsoft/rayfin-client';
import { browserSession } from '@microsoft/rayfin-auth';
import { dataService } from '@microsoft/rayfin-data';
import { functionsService } from '@microsoft/rayfin-functions';
import type { AppSchema } from '../../rayfin/data/schema';
import type { AppFunctionsSchema } from '../../rayfin/functions/src/types';

export const rayfinClient = RayfinClient.create({
  baseUrl: import.meta.env.VITE_RAYFIN_API_URL,
  publishableKey: import.meta.env.VITE_RAYFIN_PUBLISHABLE_KEY,
  auth: browserSession({ storage: true }),
  services: {
    data: dataService<AppSchema>(),
    functions: functionsService<AppFunctionsSchema>(),
  },
});

export type AppClient = typeof rayfinClient;
```

The service uses the client's shared, authenticated transport and delegates to `createFunctionsApi`. Set `functionsBaseUrl` on `RayfinClient.create` to change function routing only; data, connectors, and storage keep using `baseUrl`. It replaces 1.x's `new RayfinClient<AppSchema, AppFunctionsSchema>(...)`; see [Migrate from 1.x](/docs/reference/sdk/rayfin-client#migrate-from-1x).

## `FunctionsSchema`

```typescript
type FunctionsSchema = Record<string, { input: any; output: any }>;
```

Generated projects export an `AppFunctionsSchema` from `rayfin/functions/src/types.ts`:

```typescript title="rayfin/functions/src/types.ts"
export type AppFunctionsSchema = {
  greet: {
    input: { firstName: string; lastName: string };
    output: string;
  };
  getEntries: {
    input: Record<string, never>;
    output: { id: string; message: string }[];
  };
};
```

Pass that schema as the type argument of `functionsService<AppFunctionsSchema>()`. Schemas provide compile-time types only; they do not validate inputs or outputs at run time.

## `FunctionClient`

```typescript
class FunctionClient<TInput = any, TOutput = any> {
  constructor(apiClient: ApiClient, functionName: string);

  invoke(
    ...args: TInput extends void | Record<string, never>
      ? [params?: undefined, options?: InvokeOptions]
      : [params: TInput, options?: InvokeOptions]
  ): Promise<TOutput>;
}
```

`invoke()` returns the function output directly as `Promise<TOutput>`. It does not return the transport envelope.

| Function shape | Call form |
| --- | --- |
| Input function | `invoke(params)` or `invoke(params, options)` |
| No-input function | `invoke()` or `invoke(undefined, options)` |

A lone argument is always treated as function input, never as options.

## `InvokeOptions`

```typescript
interface InvokeOptions {
  headers?: Record<string, string>;
  timeoutMs?: number;
}
```

`timeoutMs` defaults to 250,000 ms and is capped at that same Fabric UDF host limit. Non-positive, non-finite, or missing values use the default.

## Invocation route

When the client was created with `functionsBaseUrl`, `FunctionClient` posts to:

```text
${functionsBaseUrl}/api/<functionName>
```

Otherwise it posts to the deployed Fabric route:

```text
${baseUrl}/functions/<functionName>/invoke
```

## Errors

`FunctionClient.invoke()` throws on failure. Catch `FunctionsError` before a generic error handler when you need function-specific messages or codes. Import `NetworkError` and `SdkError` by name from `@microsoft/rayfin-client`. [Changed in 2.0](/docs/reference/changelog#rayfin-20)

```typescript title="src/features/greet.ts"
import { NetworkError } from '@microsoft/rayfin-client';
import { FunctionsError } from '@microsoft/rayfin-functions';
import { rayfinClient } from '../services/rayfinClient';

export async function logGreeting(): Promise<void> {
  try {
    const result = await rayfinClient.functions.greet.invoke({
      firstName: 'Ada',
      lastName: 'Lovelace',
    });
    console.log(result);
  } catch (error) {
    if (error instanceof FunctionsError) {
      console.error(error.code, error.message);
    } else if (error instanceof NetworkError) {
      console.error('Network failure while invoking the function.');
    } else {
      throw error;
    }
  }
}
```

| Failure | Error |
| --- | --- |
| Backend response contains `errors` or non-success `status` | `FunctionsError` with code `FUNCTION_EXECUTION_ERROR`. |
| Unexpected invocation failure | `FunctionsError` with code `UNKNOWN_FUNCTION_ERROR`. |
| Network failure | `NetworkError`, propagated unchanged. |
| Other SDK failure | `SdkError`, propagated unchanged. |

The backend `invocationId` is logged with `console.debug` as `[rayfin-functions] <name> invocationId=<id>`.

## `FunctionInvocationResponse`

```typescript
interface FunctionInvocationResponse<TOutput = any> {
  functionName: string;
  invocationId: string;
  status: string;
  output: TOutput;
  errors: Array<string | Record<string, any>>;
}
```

This is the wire envelope. `invoke()` unwraps and returns `output`, auto-parsing JSON-encoded output strings and inner `{ output: <value> }` envelopes when present.
