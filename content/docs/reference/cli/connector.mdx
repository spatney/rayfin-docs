---
title: rayfin connector
appliesTo: "@microsoft/rayfin-cli >= 1.36"
description: rayfin connector manages external Fabric sources, from discovery and registration through inspection and invocation.
---

[Changed in 1.36](/docs/reference/changelog#rayfin-136)

`connector` is always registered. No connector feature-flag opt-in is required.

Use `rayfin connector` to discover existing Microsoft Fabric sources, register them in
`rayfin.yml`, inspect their read shape, and invoke configured operations. For the workflow
and app-code model, start with [Connectors](/docs/connectors); this page is the command
reference.

```bash
npx rayfin connector <command>
```

## Connector types

| Type | Fabric item | Category | Operations | Auth default | Version |
| --- | --- | --- | --- | --- | --- |
| `fabric-sqlanalytics` | Lakehouse SQL analytics endpoint | Category A | `read` | `application` [Changed in 1.36](/docs/reference/changelog#rayfin-136) | No |
| `fabric-warehouse` | Warehouse | Category A | `read`, `create`, `update`, `delete` | `application` [Changed in 1.36](/docs/reference/changelog#rayfin-136) | No |
| `fabric-sqldatabase` | SQL Database | Category A | `read`, `create`, `update`, `delete` | `application` [Changed in 1.36](/docs/reference/changelog#rayfin-136) | No |
| `fabric-semanticmodel` | Semantic model | Category B | `executeQuery` | `delegated` (only) | Pinned to `"1"` by `connector add` |
| `fabriciqmcp` | None (itemless) | Category B | `executeQuery` | `delegated` (only) [New in 2.0](/docs/reference/changelog#rayfin-20) | Pinned to `"1"` by `connector add` |
| `eventhouse` | KQL Database | Category B | `executeQuery`, `executeCommand` | `application` (only); existing entries only [Changed in 2.0](/docs/reference/changelog#rayfin-20) [Experimental](/docs/reference/changelog#feature-status) | `"1"`; new authoring held |

Category A connectors generate entity configuration for Data API Builder. Category B
connectors expose function-style operations.

`connector types`, `connector search`, and `connector add` list only authorable types. In
2.0.0, `eventhouse` is absent, and `connector add --type eventhouse` fails with
`Connector type "eventhouse" is not available in this release. Supported types: [fabric-sqlanalytics, fabric-warehouse, fabric-sqldatabase, fabric-semanticmodel, fabriciqmcp].`

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

The 1.36 `kusto` type is renamed to `eventhouse`. `--type kusto` fails as an unknown connector
type, and `rayfin up` rejects `type: kusto` entries. Existing Eventhouse entries still
validate, deploy, and invoke. See [Connectors](/docs/connectors),
[Fabric SQL sources](/docs/connectors/sql-sources),
[Semantic models](/docs/connectors/semantic-models), [Fabric IQ](/docs/connectors/fabric-iq),
and [Eventhouse](/docs/connectors/eventhouse).

## Subcommands

The registered subcommands are `search`, `add`, `list`, `remove`, `types`, `inspect`, and
`invoke`.

## Connector names

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Connector names are case-insensitive. `connector add` stores new names in lowercase.
`connector remove`, `connector invoke`, `connector inspect --name`, and
`up connector apply --name` match the name you pass case-insensitively and then use the
spelling in `rayfin.yml`. An exact match wins; when several entries differ from the name only
by case, the command fails and lists the candidates.

## `connector search`

```bash
npx rayfin connector search [query] --workspace-id <id> --type <type>
npx rayfin connector search [query] --all-workspaces --type <type>
npx rayfin connector search [query]
```

Searches Fabric items that the signed-in identity can add as connectors. It returns
warehouses, SQL databases, Lakehouses, and semantic models; it never returns Eventhouse KQL
databases or the itemless `fabriciqmcp` connector. Use one of these scopes:

| Scope | Required flags | Behavior |
| --- | --- | --- |
| Single workspace | `--workspace-id <id>` and `--type <type>` | Searches one workspace. |
| Tenant-wide | `--all-workspaces` and `--type <type>` | Searches all accessible workspaces. |
| Deployed project | No scope flags | Searches every workspace recorded in the project's deployments; `--type` is optional. |

| Flag | Description |
| --- | --- |
| `[query]` | Optional case-insensitive item-name filter. |
| `--query <text>` | Same filter as `[query]`; wins when both are provided. |
| `--workspace-id <id>` | Search one Fabric workspace. Requires `--type`. |
| `--all-workspaces` | Search every workspace the signed-in identity can access. Requires `--type`. |
| `--type <type>` | Narrow to one or more comma-separated connector types. Required with explicit workspace scope. |
| `--limit <n>` | Limit non-interactive output to the first `n` results. |
| `--output interactive\|plain\|json` | Select output mode. |
| `--json` | Emit one JSON object and skip the interactive picker. |
| `-v, --verbose` | Enable verbose output. Cannot be combined with `--json`. |
| `-y, --yes` | Auto-accept prompts in the interactive add handoff. |

With `--json`, the command emits `{ status, query, scope, count, sources }`. Each result in
`sources` includes a suggested name and a ready-to-run `addCommand`.

## `connector add`

```bash
npx rayfin connector add --type fabric-sqldatabase --workspace-id <id> --item-id <id> --name sales
npx rayfin connector add --type fabriciqmcp --name assistant
```

Registers one source in `rayfin/rayfin.yml` and scaffolds `rayfin/connectors/<name>/`.

| Flag | Description |
| --- | --- |
| `--type <type>` | Required. One of the authorable connector types: `fabric-sqlanalytics`, `fabric-warehouse`, `fabric-sqldatabase`, `fabric-semanticmodel`, or `fabriciqmcp`. |
| `--workspace-id <id>` | Fabric workspace ID, required for every type except `fabriciqmcp`. Must be a literal value; `${VAR}` placeholders are rejected. |
| `--item-id <id>` | Fabric item ID, required for every type except `fabriciqmcp`. Must be a literal value; `${VAR}` placeholders are rejected. |
| `--name <name>` | Connector name, stored in lowercase. If omitted, the CLI derives one from the Fabric item display name; `fabriciqmcp` has no item, so the name is required. Must match `/^[a-zA-Z0-9\-_]+$/` and be at most 256 characters. |
| `--operations <ops>` | Comma-separated subset of allowed operations. This can narrow the catalog defaults but cannot widen them; there is no `all` meta-operation. |
| `--auth <type>` | `delegated` (run each call as the signed-in caller) or `application` (run each call as the app owner). Omit it to use the type's default. Validated against the type's allowed auth types. [New in 2.0](/docs/reference/changelog#rayfin-20) |
| `-y, --yes` | Auto-accept confirmation prompts, including overwriting an existing connector. |
| `-v, --verbose` | Enable verbose output. |
| `--json` | Emit machine-readable JSON. |

The command verifies the Fabric item, writes the `connectors:` entry, and writes
`rayfin/connectors/<name>/schema.ts`. For Category A it also runs schema discovery and
writes `metadata.json`. For `fabric-semanticmodel` and `fabriciqmcp`, it writes the complete
generated `schema.ts`. Versioned Category B types get the catalog `defaultVersion`, which is
`"1"` today. Then it regenerates the app wiring in `src/lib/connectors.ts`; see
[Review generated app wiring](/docs/connectors/adding#review-generated-app-wiring).

[New in 2.0](/docs/reference/changelog#rayfin-20)

Before adding an item-backed connector, the command reads the runtime settings of the app's
recorded deployments in the target workspace and rejects an item that is their managed
database. Use the app's data service for that database. If the settings cannot be read, the
command fails without changing project files.

`connector add` does not install packages. It prints a version-pinned `npm install` command;
with `--json`, the same data appears under `install.packages` and `install.command`.

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

The `--json` result also reports `name` (the name written to `rayfin.yml`), `requestedName`
when the name you passed was spelled differently, `auth`, `operations`, `overwritten`,
`warnings`, `schemaDiscovery` for Category A, and the `wiring` outcome, whose `action` is
`written`, `unchanged`, `discovered`, `manual`, `absent`, or `ambiguous`.

Re-adding a name that already exists in any casing overwrites that entry after a prompt, or
with `--yes`. It keeps the existing spelling, preserves entity files, rewrites
`metadata.json`, and resets `auth.type` to the type's default unless you pass `--auth`.
`--yes` also replaces a hand-written Category A aggregate `schema.ts` with a placeholder.

## `connector list`

```bash
npx rayfin connector list
```

Lists connectors declared in `rayfin.yml`. It does not call Fabric or the deployed workload.

| Flag | Description |
| --- | --- |
| `-v, --verbose` | Include catalog metadata for each connector. Cannot be combined with `--json`. |
| `--json` | Emit the configured connector entries as JSON. |

## `connector remove`

```bash
npx rayfin connector remove sales --yes
```

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

Removes the named connector entry from `rayfin.yml` and regenerates the app wiring. It keeps
the whole `rayfin/connectors/<name>/` directory, including entity files; only legacy
temporary files under `rayfin/.temp/sources/<name>/` are deleted. Preserved files can still
be compiled during `rayfin up`, so keep their dependencies until you have backed them up and
deleted or excluded them.

| Flag | Description |
| --- | --- |
| `-y, --yes` | Auto-accept confirmation prompts. Required in non-interactive contexts for existing connectors. |
| `-v, --verbose` | Enable verbose output. |
| `--json` | Emit machine-readable JSON. |

JSON output for a removed connector is
`{ status, action: 'connector.remove', name, requestedName?, removed, directoryDeleted: false, recovery, wiring }`.
Removing a name that is not declared succeeds with `removed: false`.

## `connector types`

```bash
npx rayfin connector types --verbose
```

Lists the connector catalog.

| Flag | Description |
| --- | --- |
| `-v, --verbose` | Add category, default auth, dialect, operations, discoverable item types, required version, and client packages. |
| `--output interactive\|plain\|json` | Select output mode. |
| `--json` | Emit the catalog as JSON. |

[Changed in 1.36](/docs/reference/changelog#rayfin-136)

`--json` emits `{ status, schemaVersion, count, types }`. Each type includes `type`,
`category`, `description`, `defaultAuth`, `allowedAuthTypes`, `dialect`,
`allowedOperations`, `requiredConfig`, `discoverableItemTypes`, `requiresVersion`, optional
`defaultVersion`, and version-pinned `packages`. In 2.0.0, `fabriciqmcp` reports an empty
`requiredConfig` and no discoverable item types.

## `connector inspect`

```bash
npx rayfin connector inspect --name sales
npx rayfin connector inspect --name sales --entity dbo.Customers --rows 10
npx rayfin connector inspect --workspace-id <id> --item-id <id> --type fabric-warehouse --query queries/sample.sql
```

Inspects a source in read-only mode. It supports `fabric-sqlanalytics`,
`fabric-warehouse`, `fabric-sqldatabase`, and `fabric-semanticmodel`. Any other type fails
with `Unsupported connector type: <type>`, for example
`Unsupported connector type: eventhouse`.

| Flag | Description |
| --- | --- |
| `--name <name>` | Select a connector declared in `rayfin.yml`, matched case-insensitively. Mutually exclusive with direct selectors. |
| `--workspace-id <id>` / `--workspace <name>` | Direct mode workspace selector. Use with `--item-id` or `--item` and `--type`. |
| `--item-id <id>` / `--item <name>` | Direct mode item selector. Use with a workspace selector and `--type`. |
| `--type <type>` | Connector type for direct mode. |
| `--url <portal-url>` | Semantic-model portal URL; extracts workspace and item IDs. Cannot be combined with other selectors. |
| `--entity <name>` | Structured entity sampling mode. |
| `--query <path>` | Raw query mode. Path must point to a `.sql` or `.dax` file inside the project. |
| `--rows <n>` | Row cap. Default is 100 for entity listing and 10 for entity or query modes; maximum is 100. |
| `-v, --verbose` | Enable verbose output. |
| `--output interactive\|plain\|json` | Select output mode. |
| `--json` | Emit a machine-readable JSON object. |

Inspect has three modes:

| Mode | How to select it | Query shape |
| --- | --- | --- |
| Entity listing | Omit `--entity` and `--query` | SQL uses `INFORMATION_SCHEMA.TABLES`; DAX uses `INFO.TABLES()`. |
| Structured entity | Pass `--entity <name>` | SQL builds `SELECT TOP(n) * FROM <entity>`; DAX builds `EVALUATE TOPN(n, '<entity>')`. |
| Raw query | Pass `--query <path>` | Runs the `.sql` or `.dax` file verbatim. |

SQL inspect accepts only read queries that start with `SELECT` or `WITH`; DML and DDL are
rejected. DAX inspect requires the query to start with `EVALUATE`.

## `connector invoke`

```bash
npx rayfin connector invoke mymodel executeQuery --input '{"query":"EVALUATE TOPN(10, Sales)"}'
npx rayfin connector invoke --name mymodel --operation executeQuery --file payload.json
```

Invokes one configured operation. The positional connector name and operation also have flag
forms, `--name` and `--operation`; flag values win over positionals.

| Flag | Description |
| --- | --- |
| `<connector-name>` | Connector name declared in `rayfin.yml`, matched case-insensitively. |
| `<operation>` | Operation to invoke. |
| `--name <name>` | Connector name flag form; wins over the positional. |
| `--operation <operation>` | Operation flag form; wins over the positional. |
| `--input '<json>'` | Inline JSON payload. Exactly one of `--input` or `--file` is required. |
| `--file <path>` | JSON payload file, resolved against the project root. The resolved path must stay inside it; `..\` escapes are rejected before the file is read. |
| `-v, --verbose` | Enable verbose output. Cannot be combined with `--json`. |
| `--output interactive\|plain\|json` | Select output mode. |
| `--transport <mode>` | `auto` (default) picks per connector type; `deployed` forces the deployed BaaS route and needs a Rayfin app-session token in `RAYFIN_TOKEN`. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| `--output-file <path>` | Write the full result to this file; inline output remains unless it exceeds `--max-inline-bytes`. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| `--max-inline-bytes <bytes>` | Spill to a file and show only a preview when serialized output exceeds this many bytes; `0` always prints inline. Default `8192`. [New in 1.36](/docs/reference/changelog#rayfin-136) |
| `--json` | Emit one machine-readable JSON object. |

Operation names match case-insensitively against the connector's `operations:` list. If the
entry has no operations, the command falls back to the connector type's full catalog
allowlist.

The payload is the operation's input. A semantic model takes `{ "query": "<DAX>" }`; an
Eventhouse connector takes a saved query, `{ "queryId": "<id>", "parameters": { ... } }`.

### Invoke transports

With `--transport auto`, `fabric-semanticmodel` calls Fabric and Power BI directly under the developer's own identity. It works with or without `rayfin up`, and it requires `workspaceId` and `itemId` under the connector's `config:` block.

[Changed in 2.0](/docs/reference/changelog#rayfin-20)

The direct semantic-model path queries the model-scoped `executeDaxQueries` endpoint, so the
developer needs Read and Build permissions on the semantic model, not write access to the
workspace.

`--transport deployed` opts out of that shortcut and exercises the deployed BaaS route.

Every other type, including `eventhouse`, POSTs to the deployed item at
`/__private/connectors/<name>/invoke` and requires a prior `rayfin up`.

### Invoke token handling

`rayfin login` consents to the Fabric scope, not the Power BI scope the semantic-model path
needs. Interactively, the CLI prompts to complete Power BI consent. With `--json`, token
acquisition is silent-only so prompts cannot corrupt the single-JSON-object contract; if
consent is still needed, the command fails and tells you to drop `--json` or set
`RAYFIN_TOKEN`. When `RAYFIN_TOKEN` is set, it is passed through unchanged and its audience
is decoded and checked locally.

### Invoke output

Success emits `{ status: 'ok', connector, operation, output }`. When output spills, the envelope also includes `outputFile`, `outputBytes`, `outputTruncated`, and `previewItems`.

A resolved call is not
automatically a success: a normalizing connector reports failure as `status: 'error'`, and a
connector returning a raw envelope reports failure as `status: 'Failed'`. The CLI converts
either failure shape into a non-zero exit.

[New in 2.0](/docs/reference/changelog#rayfin-20)

When several `rayfin.yml` entries differ from the requested name only by case and none
matches exactly, the command fails, and the `--json` error lists them under `candidates`.

> [!NOTE]
> Rayfin 1.36.1 coerces semantic-model Arrow Int64 values, including Union/Variant Int64s, before CLI output is serialized. Safe Int64 values should no longer print `Do not know how to serialize a BigInt`. Values outside JavaScript's safe integer range surface as connector `overflow` errors. [Changed in 1.36.1](/docs/reference/changelog#rayfin-1361)

### Invoke errors

| Message | Fix |
| --- | --- |
| `Missing required connector invoke arguments` | Supply both the connector name and the operation. |
| `Choose exactly one payload source` / `Missing payload input` | Pass exactly one of `--input` or `--file`. |
| `Input file must be inside the project` | Use a relative path under the project root. |
| `Operation "<op>" is not allowed for connector "<name>"` | Check the connector's `operations:` in `rayfin.yml`, or the type's allowlist. |
| `missing workspaceId/itemId in rayfin.yml` | Add both under `config:`, or re-run [`connector add`](#connector-add). |
| `Access token has the wrong audience for the Power BI query API` | Unset or replace `RAYFIN_TOKEN`, or re-run without `--json` to consent interactively. |
| `Invalid --max-inline-bytes value: <value>.` | Pass a non-negative whole number of bytes, or `0` to always print inline. |
| `No remote endpoint configured` | The non-semantic-model transport, or `--transport deployed`, needs a deployed item; run `npx rayfin up` first. |

## `up connector apply`

[Preview](/docs/reference/changelog#feature-status) [Changed in 1.36](/docs/reference/changelog#rayfin-136)

```bash
npx rayfin up connector apply
npx rayfin up connector apply --name inventory
```

Generates DAB configuration for declared Category A connectors, checks reserved and duplicate GraphQL entity names, and POSTs each generated config to the deployed workload.

It requires a prior `npx rayfin up` so the remote endpoint and connector settings exist. Category B connectors are reported as skipped because they do not have generated GraphQL DAB config.

| Flag | Description |
| --- | --- |
| `--name <name>` | Apply only the named connector instead of every entry in `rayfin.yml`. Matched case-insensitively. [Changed in 2.0](/docs/reference/changelog#rayfin-20) |
| `-v, --verbose` | Enable verbose output. |
| `--json` | Emit `{ status, generate, results, steps, duration }`. `status` is `partial` when generation or apply failed for any connector. |

`npx rayfin up --json` also includes connector generation and apply outcomes in the deployment `steps` map, with connector step keys namespaced as `connector:<name>`.

[New in 2.0](/docs/reference/changelog#rayfin-20)

`up connector apply`, `rayfin up`, and `rayfin dev` validate the `connectors:` block before
any write: they reject two entries whose names differ only by case, `additionalPayload` on a
Category A connector, and an `additionalPayload` over 64 KiB or 32 levels deep. With `--json`,
these failures report the `invalid-connectors` code and a `hint`.

```prompt title="Register a Fabric SQL Database connector"
Add a Rayfin connector named "sales" for my Fabric SQL Database using
`npx rayfin connector add --type fabric-sqldatabase --workspace-id <workspace-id>
--item-id <item-id> --name sales`, then run the version-pinned npm install command it
prints, verbatim. Show me the resulting rayfin.yml entry, the scaffolded
rayfin/connectors/sales/schema.ts, and the `wiring` outcome the command reported. Do not
pass `--yes` if a connector named sales already exists; ask me first.
```
