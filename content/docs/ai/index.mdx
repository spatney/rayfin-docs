Most models have never seen Rayfin. Left to guess, they produce code that looks right and
fails at deploy time: entities with no permission decorator, `@text()` fields with no
length, `onAuthStateChange` instead of `onSessionChange`.

Three things fix that. Do them once per project.

## 1. Install agent files

```bash
npx rayfin init ai-files install
```

This writes `AGENTS.md`, `.agents/skills/rayfin/SKILL.md`, and an `.mcp.json` entry into
your project. Almost every coding agent reads at least one of them on every task, so the
Rayfin rules travel with the repository instead of living in your chat history.

See [Agent files in your project](/docs/ai/agent-files) for what each file does and how
conflicts are handled.

## 2. Connect the docs server

The `.mcp.json` written above wires up `@microsoft/rayfin-mcp`, which serves the
documentation bundled inside your installed packages. Its answers are locked to the exact
versions in your `node_modules`, so an agent can confirm a signature instead of inventing
one.

See [The Rayfin MCP server](/docs/ai/mcp-server) for the available tools and the CLI
fallback.

## 3. Give it the rules

[Rules for coding agents](/docs/ai/rules) is the condensed list of everything that changes
whether generated Rayfin code works. It is worth pasting into a long-running session even
with agent files installed.

## Pointing an agent at these docs

Every page on this site is available as raw Markdown — append `.md` to any URL. That lets
an agent read documentation without HTML parsing, and works from any HTTP client.

```bash
curl https://rayfin.ai/docs/data/querying.md
```

| Resource | What it is |
| --- | --- |
| `<any-route>.md` | That page as raw Markdown, with a YAML header identifying it |
| [`/llms.txt`](/llms.txt) | Index of every page with a one-line description |
| [`/llms-full.txt`](/llms-full.txt) | The entire documentation set in one file |
| [`/AGENTS.md`](/AGENTS.md) | Operating instructions for agents, at the site root |

Use this when the agent has no Rayfin project on disk yet — planning, scaffolding, or
answering "how does Rayfin do X".

```prompt title="Give an agent Rayfin knowledge"
Read https://rayfin.ai/llms.txt to learn what the Rayfin documentation covers, then read
https://rayfin.ai/docs/ai/rules.md and https://rayfin.ai/docs/reference/known-limitations.md
before writing any Rayfin code.

Every page on that site is available as raw Markdown by appending .md to its URL — for
example https://rayfin.ai/docs/data/querying.md. Fetch the specific pages you need as you
go rather than guessing at APIs.
```

## Which source to use

| | This site | MCP server |
| --- | --- | --- |
| Source | Published documentation | The packages installed in your project |
| Version | Latest published | Exactly what you have installed |
| Needs a project on disk | No | Yes |
| Best for | Concepts, planning, CLI and SDK reference | Confirming a signature for your version |

Use both. This site teaches the model how Rayfin works; the MCP server confirms details
against the version in front of it.
