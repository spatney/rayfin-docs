Prompts you can hand to a coding agent as-is. Each one is self-contained: it states the
project context, the task, and the constraints that make Rayfin code correct.

Individual pages carry prompts for their own topic. This page collects the ones you are
most likely to reach for.

## Getting grounded

```prompt title="Give an agent Rayfin knowledge"
Read https://rayfin.ai/llms.txt to learn what the Rayfin documentation covers, then read
https://rayfin.ai/docs/ai/rules.md and https://rayfin.ai/docs/reference/known-limitations.md
before writing any Rayfin code.

Every page on that site is available as raw Markdown by appending .md to its URL — for
example https://rayfin.ai/docs/data/querying.md. Fetch the specific pages you need rather
than guessing at APIs.
```

## Scaffolding

```prompt title="Create a new Rayfin app"
Create a new Rayfin project called my-app using `npm create @microsoft/rayfin@latest`.
Choose a template that includes auth and data. Then start the backend with `npx rayfin up`
and the frontend with `npm run dev`, and tell me the local URL.

Constraints: Rayfin uses TC39 Stage 3 decorators — never enable experimentalDecorators or
emitDecoratorMetadata, and make sure ESNext.Decorators is in the tsconfig lib array.
```

```prompt title="Add Rayfin to an existing project"
My project already has source code. Add Rayfin to it by running `npx rayfin init` from the
project root. Enable the auth and data services and use the mssql dialect. Do not scaffold
a new template over my existing code. Afterwards, run `npx rayfin init ai-files install` so
the project carries Rayfin agent context, and show me the resulting rayfin/rayfin.yml.
```

## Data modeling

```prompt title="Add an entity"
Add a new entity to my Rayfin project in rayfin/data/ and register it in
rayfin/data/schema.ts.

Follow these Rayfin rules exactly:
- Use @entity() on the class and exactly one type decorator on every field.
- Every @text() field must set a max length, e.g. @text({ max: 200 }). NVARCHAR(MAX) breaks
  GraphQL schema generation on MSSQL.
- Fields are required by default. For nullable fields use { optional: true } and ? together.
- Add an explicit permission decorator. An entity with no permission decorator silently
  gets full CRUD for any signed-in user.
- Register the entity in schema.ts as part of the AppSchema type.

Then apply the schema with `npx rayfin up` and verify with `npx rayfin up status`.
```

```prompt title="Add a relationship between two entities"
Add a relationship between two entities in my Rayfin project.

Follow these Rayfin rules exactly:
- Use @one(() => Target) with a lazy arrow function on the owning side, and @many(() => Target)
  on the inverse side.
- Import the entity class with `import`, not `import type` — the decorator needs the runtime
  class value.
- Rayfin auto-generates the foreign key column as {property}_id. Only declare it explicitly
  if application code needs it, and if you do, type it @uuid() to match the primary key.
- Many-to-many is not supported. If I need it, create an explicit join entity with two @one()
  fields and explain why.

Then apply the schema with `npx rayfin up`.
```

```prompt title="Add per-user row-level security"
Add row-level security to an entity in my Rayfin project so each signed-in user can only
read and write their own rows.

Use the @role or @authenticated decorator with a policy comparing claims.sub to the row's
user id field, for example:
  policy: (claims, item) => claims.sub.eq(item.user_id)

Note that a user_id field derived from claims.sub is @text(), not a @uuid() foreign key.
Make sure the field is populated on create. Then apply the schema with `npx rayfin up` and
tell me how to verify the policy works.
```

## Querying

```prompt title="Write a data access layer"
Write a typed data access module for an entity in my Rayfin project, exposing list, get,
create, update, and delete functions.

Follow these Rayfin rules exactly:
- Always use client.data.<Entity> — never raw fetch() or hand-built GraphQL.
- Query chain order is .select() -> .where() -> .orderBy() -> .execute().
- Use findById(id) for a single record. findByPk does not exist.
- Filter on foreign keys using the {property}_id column, not a dot-path. Dot-paths are for
  .select() only.
- Sort directions are lowercase 'asc' or 'desc'.
- Use .first(n).executePaginated() with .after(endCursor) for lists that can exceed one page.
- count() does not exist on the fluent client.
```

## Auth

```prompt title="Add Fabric SSO sign-in"
Add Fabric SSO sign-in to my Rayfin app.

Enable fabric auth in rayfin/rayfin.yml, install @microsoft/rayfin-auth-provider-fabric, and
wire it into the client. Use onSessionChange to react to session changes — onAuthStateChange
does not exist on the Rayfin auth client. Session objects are opaque, so gate UI on
isAuthenticated or the presence of a user property rather than introspecting the session.

Fabric SSO's popup flow works from a local Vite dev server as well as a deployed Fabric
app, as long as its origin is registered in allowedRedirectUris. Explain how I test sign-in
in both places.
```

## Deployment

```prompt title="Build and deploy"
Deploy my Rayfin app to Microsoft Fabric. Run the workflow yourself rather than printing
steps for me:

1. `npx rayfin login`
2. `npx rayfin up`
3. `npx rayfin up status`

`rayfin up` builds and deploys the static app and applies pending schema migrations. If I
have added or changed an entity, confirm after deploying that the change actually applied —
a deploy can report success while a new entity is not yet readable. If it did not apply, run
`npx rayfin up db apply` and explain what happened.

Do not pass --force without showing me what it would change first.
```

```prompt title="Diagnose a failing deployment"
My Rayfin deployment is failing. Diagnose it.

Start by fetching https://rayfin.ai/docs/deploy/troubleshooting.md and
https://rayfin.ai/docs/reference/known-limitations.md.

Then check, in order:
- Is `services.data.dialect` set in rayfin/rayfin.yml? Omitting it while data is enabled
  fails with "Dialect is required when Data module is enabled".
- Are `services.auth` and `services.data` both declared explicitly, even if disabled?
- Do all @text() fields set a max length? NVARCHAR(MAX) causes an internal server error at
  runtime after an otherwise successful deploy.
- What does `npx rayfin up status` report?

Report what you find before changing anything.
```

## Writing prompts of your own

A prompt that works reliably against Rayfin usually contains three things:

1. **Where the work happens** — `rayfin/data/`, `rayfin/rayfin.yml`, the project root.
2. **The constraints that are easy to get wrong** — `max` on `@text()`, explicit permission
   decorators, `onSessionChange`, `findById`, lowercase sort directions.
3. **The verification step** — `rayfin up status`, or the specific behaviour to check.

Without the constraints, a model will produce plausible code that fails at deploy time
rather than at compile time. [Rules for agents](/docs/ai/rules) is the full list.
